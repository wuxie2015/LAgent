# Shell 工具、持久化记忆与通用提示词变更说明

- 文档日期：2026-10-30（Asia/Tokyo）
- 文档类型：已实施变更记录与架构说明
- 依据：本次对话中的实施记录，以及编写时对当前源码的核对。
- 范围：Shell 工具接入、基础持久化记忆、通用系统提示词三项变更。

## 1. 变更概览

项目从主要面向网页搜索的终端助手，扩展为能够调用本机 Shell、恢复历史对话的通用终端 Agent。

| 变更 | 原有行为 | 当前行为 |
| --- | --- | --- |
| 工具能力 | 注册网页搜索，执行器固定传query | 同时注册web_search与shell，按关键字分发参数 |
| 对话记忆 | 当前进程内维护消息 | CLI将消息保存到项目根目录memory/history.json，重启恢复 |
| 系统提示词 | 主要约束新闻搜索与来源核验 | 覆盖一般问答、执行任务、搜索、本机工作、文件修改、记忆与验证 |

三项均已在源码实现。最近10轮、长期事实、任务状态属于另一个待实施设计，不能与本次基础记忆混淆。

## 2. 当前架构和调用路径

```text
python -m src / ./run.sh
    → application.cli.main
        → 加载Settings、日志和system.md
        → 创建Memory(system_prompt, DEFAULT_MEMORY_PATH)
        → 创建OllamaClient
        → 注册WebSearchTool、ShellTool
        → 创建Agent
            → 读取用户输入并追加到Memory
            → 将完整messages与工具definition交给模型
            → 模型返回tool_calls
                → 校验工具名，解析arguments
                → 按工具实例调用run(**arguments)
                → 将结果追加到Memory，再请求模型
            → 无tool_calls时返回最终文本
```

domain/interface.py声明模型和工具契约；application组织用例；service提供Ollama适配；tools实现可调用操作；common负责配置、提示词和日志。

基础Memory目前位于domain且包含文件IO，是现阶段的简化实现。未来分层记忆设计会将存储移入适配层；本次记录不声称已经完成该重构。

## 3. Shell 工具

### 3.1 相关文件

| 文件 | 作用 |
| --- | --- |
| `src/tools/shell.py` | ShellTool定义、参数校验、进程执行、超时和输出处理 |
| `src/tools/__init__.py` | 导出ShellTool |
| `src/application/cli.py` | 创建并注册ShellTool实例 |
| `src/application/agent.py` | 工具参数分发与错误回传 |
| `src/domain/interface.py` | AgentTool改为接收关键字参数 |
| `tests/test_shell.py` | 验证执行、错误码、超时、截断与Agent接入 |

### 3.2 注册方式

CLI显式组装工具：

```python
tools=[
    WebSearchTool(settings.tavily_api_key, settings.search_result_limit),
    ShellTool(),
]
```

Agent将其转成名称到实例的字典：

```python
self.tools = {tool.name: tool for tool in tools}
```

每次请求模型时发送这些实例的definition。模型看到工具名、功能和参数格式，决定是否返回结构化调用。当前没有目录自动扫描、动态插件发现或工具安装机制。

### 3.3 参数契约

工具名：`shell`。

| 参数 | 类型 | 必填 | 默认与限制 |
| --- | --- | --- | --- |
| command | string | 是 | 非空字符串，由/bin/sh执行 |
| cwd | string | 否 | 默认当前Agent进程工作目录；展开~并解析路径；须为已存在目录 |
| timeout | integer | 否 | 默认30秒，范围1–300；拒绝bool和其他类型 |

工具schema设置additionalProperties=false。ShellTool执行前还校验关键参数；未知参数由Python调用失败进入Agent统一工具错误回传。

调用示例，路径应替换为实际项目位置：

```json
{
  "command": "pwd && ls -la",
  "cwd": "/Users/zhanglin/Documents/project/lin-agent",
  "timeout": 30
}
```

### 3.4 返回结构

正常启动后返回字段如下，命令失败仍可以有完整结构：

```json
{
  "cwd": "/Users/zhanglin/Documents/project/lin-agent",
  "exit_code": 0,
  "timed_out": false,
  "stdout": "/Users/zhanglin/Documents/project/lin-agent\n",
  "stderr": "",
  "stdout_truncated": false,
  "stderr_truncated": false
}
```

参数错误、路径无效、进程无法启动等情况返回error对象。模型应区分工具报错、命令非零退出、超时与业务目标是否成功。

### 3.5 执行实现

- 使用subprocess.Popen(command, shell=True, executable="/bin/sh")。
- stdin为DEVNULL，没有交互式标准输入。
- start_new_session=True，为超时终止进程组提供基础。
- stdout、stderr写临时文件，避免把无限输出直接缓存在内存中。
- wait超时后对命令进程组发送SIGKILL，并等待直接子进程退出。
- 每个输出流最多读取并返回16000字节，额外读1字节判断是否截断。
- 输出按UTF-8解码，损坏字节使用替代字符。

16000是每个输出流的字节上限，不是字符数、总输出上限或磁盘写入上限。进程结束前临时文件仍可能持续增长。

进程组终止覆盖仍在该组的后代；主动脱离进程组的程序不在可靠控制范围内，因此不能保证任意后台任务都能清理干净。

### 3.6 执行器与接口变化

旧执行器固定取query并调用run(query)，不适合具有command、cwd、timeout的工具。

当前接口：

```python
class AgentTool(Protocol):
    name: str
    definition: dict[str, Any]

    def run(self, **arguments: Any) -> dict[str, Any]:
        ...
```

当前分发：

```python
try:
    return self.tools[tool_name].run(**arguments)
except Exception as exc:
    return {"error": f"工具执行失败：{exc}"}
```

WebSearchTool已有query命名参数，因此仍可通过run(query=...)调用。未知工具名在分发前由_parse_tool_call拒绝；字符串形式arguments会尝试解析成JSON，非字典参数回退为空字典，随后由具体工具报错。

同轮工具调用仍由ThreadPoolExecutor并行执行，结果按请求顺序写回。提示词要求依赖操作和写同一资源的操作串行，但当前执行器尚未实现基于读写属性的自动调度。

### 3.7 权限与边界

Shell自动执行，继承启动Agent的系统用户权限和进程环境；没有额外沙箱、cwd访问白名单、逐命令确认UI或命令白名单。

独立调用不保留cd、Shell变量或环境修改，文件等真实副作用会保留。重要删除、破坏性覆盖、部署和对外操作的授权要求由提示词约束，并非执行层强制拦截。

因此“模型被要求先确认”不能等同于“所有危险命令都有技术确认门禁”。调用方仍应检查授权与实际环境。

## 4. 基础持久化记忆

### 4.1 相关文件

| 文件 | 作用 |
| --- | --- |
| `src/domain/memory.py` | Memory、MemoryError和DEFAULT_MEMORY_PATH |
| `src/domain/__init__.py` | 对外导出记忆类型与默认路径 |
| `src/application/agent.py` | 注入Memory，用Memory追加和重置消息 |
| `src/application/cli.py` | 启用持久化、处理加载与保存错误 |
| `.gitignore` | 忽略memory/ |
| `tests/test_memory.py` | 恢复、reset及损坏文件保护测试 |

### 4.2 路径与实例化

```python
DEFAULT_MEMORY_PATH = (
    Path(__file__).resolve().parents[2] / "memory" / "history.json"
)
```

默认路径锚定项目位置，不随Shell的cwd改变。CLI使用Memory(system_prompt, DEFAULT_MEMORY_PATH)。仅创建Memory(system_prompt)时没有文件路径，只保存进程内消息；直接创建Agent但不注入memory时也采用该内存模式。

### 4.3 文件格式和上下文

history.json是消息数组，不保存system消息，例如：

```json
[
  {"role": "user", "content": "查看当前目录"},
  {"role": "assistant", "tool_calls": [{"function": {"name": "shell", "arguments": {"command": "pwd"}}}]},
  {"role": "tool", "content": "工具结果JSON字符串"},
  {"role": "assistant", "content": "当前目录为项目目录。"}
]
```

工具消息的content实际由Agent序列化，包含tool、arguments、result。示例简写仅展示消息结构。

加载后的内存messages顺序为：最新system提示词，再接文件中的用户/助手/工具历史。每次主模型调用仍发送整个messages列表，没有历史筛选或压缩。

### 4.4 保存和恢复

- append先追加消息，再保存；用户输入、模型回复、工具结果分别触发保存。
- 文件不存在时不报错，从仅含system消息的新会话开始；首次保存时创建目录。
- 写入使用UTF-8和ensure_ascii=False，方便阅读中文。
- 临时文件与目标文件处于同一目录，完成后os.replace替换目标。
- 加载时校验顶层为数组，且每项为允许role的字典；不是完整的消息协议或工具配对验证。
- 文件不可读、编码或JSON错误、结构错误会触发MemoryError；CLI显示错误并停止启动，不静默覆盖文件。

当前原子替换并未提供跨进程锁、revision、fsync持久性保证或内存事务回滚。append/reset在保存前已改变内存，保存失败后内存与磁盘可能不一致，这也是后续分层设计需要修正的地方。

### 4.5 reset语义

当前/reset：

1. 将messages重置为仅有当前system提示词。
2. 将history.json写为一个空数组。
3. CLI提示当前会话和已保存历史已清除。

退出后可以恢复未reset的历史；reset后重启不会恢复被清除的消息。本节记录的是当前行为；未来设计拟保留facts/tasks的/reset尚未实施。

### 4.6 当前尚不具备的记忆能力

- 最近10轮限制、用户轮次实体和上下文容量预算。
- 长期事实提取、去重、冲突处理及来源追溯。
- 独立任务状态、工具执行检查点和自动恢复流程。
- 原始轮次归档、历史迁移和选择性遗忘。
- 多进程安全、加密存储、语义检索。

当前历史是本地明文，并可能包含Shell参数、输出和对话中的敏感内容。Git忽略仅避免普通提交，不等于加密或脱敏。CLI目前还会输出完整模型消息，调试展示有额外暴露风险。

## 5. 通用系统提示词

### 5.1 文件和加载方式

提示词位于resource/prompt/system.md。prompt_loader.py在启动时读取，并用Asia/Tokyo当前日期替换{{CURRENT_DATE}}。

提示词更新后需重启Agent。因为system不写入history.json，所以恢复旧历史时仍使用新提示词；这不意味着旧对话中的事实和结论已被自动重新验证。

### 5.2 设计动机

原提示词围绕新闻搜索，不能充分指导一般文件操作、代码修改、任务执行和持久化历史使用。本次按项目实际工具能力改为通用协作规则，而没有引入新的Agent框架或更换模型。

参考的是官方公开指南中的设计原则，不声称复制了Codex或Claude某个产品的完整内部system prompt，也不承诺其模型专用行为可以直接迁移到当前Ollama模型。

### 5.3 内容结构

| 章节 | 主要约束 |
| --- | --- |
| 目标与协作 | 理解结果、区分解释与执行、合理自主推进、只问关键问题 |
| 工具与执行循环 | 使用实际工具定义、检查结果、避免无效循环、合理安排8次模型调用 |
| 网页搜索与事实核验 | 时效搜索、区分事件与报道日期、依证据引用来源 |
| Shell与本机工作 | /bin/sh、cwd与超时、无交互输入、参数引用及实际权限 |
| 文件与代码修改 | 先读后改、最小改动、保留用户工作、按风险验证 |
| 记忆与可信边界 | history恢复、旧信息可能过时、没有独立记忆工具、抵御外部指令注入 |
| 回答方式 | 默认中文、结果优先、区分尝试/执行/验证、不伪装完成 |

### 5.4 与当前Agent循环的适配

当前Agent在模型响应没有tool_calls时直接返回文本。因此提示词明确要求：需要执行时必须发起结构化工具调用，不能只回复“我将执行”或给出计划就停止。

max_tool_rounds名称虽然包含tool，但实际循环每次都调用模型，最终回答也占一次。提示词按“最多8轮模型调用”描述，提醒为最终回答留出空间。

提示词允许互不依赖的只读调用并行，对有依赖和共享写入资源的操作要求分轮。该规则目前由模型遵守，执行器不会独立证明所有调用互不影响。

## 7. 使用方式

重启：

```bash
./run.sh
```

对话示例：

```text
执行 pwd，查看当前目录。
查看项目 src 目录，说明主要模块。
搜索最近的 Python 官方公告并给出来源。
```

执行Shell会产生真实本机副作用。用户只要求讲解时，助手不应擅自执行修改；用户明确要求操作时，按实际授权和提示词约束执行。

退出后重新启动，CLI会恢复history.json；输入/reset会清除当前及已保存消息。
